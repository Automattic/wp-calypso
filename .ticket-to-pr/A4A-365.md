### Current Behavior

A "Duplicate Agency" warning modal already exists in the A4A signup flow. It shipped Nov 2025 by @james.kenneth.guidaven via [wp-calypso #106816](https://github.com/Automattic/wp-calypso/pull/106816) and [wpcom #194984](https://github.a8c.com/Automattic/wpcom/pull/194984), tracked in [A4A-1589](https://linear.app/a8c/issue/A4A-1589/reduce-duplicate-agency-signups). When a user enters an agency name or URL that matches an existing agency, the modal shows a warning, then offers two buttons: "Cancel" (closes the modal) and **"Continue creating new agency account"** (proceeds with the duplicate).

Result: roughly 60 duplicate signups since mid-Dec 2025 ignored the warning. Cleanup remains time-consuming when both agencies have purchase activity.

The check uses `isAgencyNameExists` and `isAgencyUrlExists` from `client/a8c-for-agencies/components/form/utils/index.ts`, which call `/wpcom/v2/agency/exists/name` and `/wpcom/v2/agency/exists/url`. The modal lives in `client/a8c-for-agencies/sections/signup/signup-v2/components/multi-step-form/contact-form/index.tsx`. There is no "Login" or invitation-help affordance on the standalone signup page, so pre-existing logged-out users have no obvious path other than the duplicate-creation button.

### Desired Behavior

Per the April 16, 2026 Slack thread in #a4a-ask between @jeffgolenski and @katiebethbrown, the modal should **block** the duplicate creation by default rather than allow bypass. When a duplicate domain is detected:

1. Replace the "Continue creating new agency account" button with copy and a "Contact support" CTA. The modal should make clear that the agency owner needs to invite them as a team member, without surfacing that the domain is what triggered the match (avoid the "change to a different bunk domain" gaming path).
2. Allow Automatticians and proxied users to bypass the block via internal-only UI (so test signups continue to work).
3. Optionally surface "Already have an account? Login" on the signup page itself for users who have already been invited and accepted (originally A4AD-91, now merged into this issue).

### Note on the underlying UX problem (Katie, 2026-05-06)

The duplicate-signup pattern is partly a mental-model gap: agencies don't see "the agency" as a container, because users log in with their personal WordPress.com accounts. The first signup silently creates the agency and makes that user the owner. Additional teammates need to be invited as team members on the existing agency by the agency owner, not create new agencies of their own.

A "Log in" CTA in the modal is misleading. A teammate cannot log in until the agency owner has invited them. The correct flow is to direct them to ask their agency owner to log in and invite them as a team member, after which they receive an email with a link to log in. The modal copy should make this clear, rather than implying a self-service path.

New mode accepts prefilled name, email, agency name, agency URL via props instead, and submits without an `agency_id`. Add a tag (e.g. `a4a_duplicate_signup_blocked`) to the submission payload so the support team can route and triage easily.
* `client/a8c-for-agencies/components/form/utils/index.ts`: keep `isAgencyUrlExists`. `isAgencyNameExists` is no longer used here; consider deprecating in a follow-up.
* New: signup-context fetch and proxy/Automattician-aware UI. Conditional "Internal Flags" section in the modal renders only when those flags come back true.

Email source: the user's email is available either via `getCurrentUser().email` (regular logged-in signup path) or via `formData.email` (magic-link signup path, where `withEmail={signupWithMagicLinkFlow}` enables the email field). The support modal prefill must source from whichever path is active.

#### Modal copy

Title: **It looks like your agency may already be part of Automattic for Agencies.**

Body:

> To get access, ask your agency owner to [invite you as a team member](https://agencieshelp.automattic.com/knowledge-base/invite-team-members/). If you're not sure who that is or need help, contact support.

Buttons:

* Primary: **Contact support** (opens `UserContactSupportModalForm` prefilled)
* Secondary: **Cancel** (closes modal, returns focus to the signup form)

Note: copy intentionally does NOT surface the matched domain, to avoid users gaming the check by entering a different bunk domain. The agency-domain variable is not interpolated anywhere in the body.

#### Internal Flags section (Automatticians and proxied users only)

Renders below the modal body in a visually distinct block.

Header: **Internal Flags**

Small italic muted text under the header, generated from whichever flags actually fired:

> *You're seeing these options because you're [proxied / logged into an A11n-owned WordPress.com account / proxied AND logged into an A11n-owned WordPress.com account].*

Below that:

* Button: **Bypass and create new agency anyway** (proceeds with the duplicate signup, sets `set_agency_test_flag(true)` on the new agency)
* Checkbox: **Don't send this signup to HubSpot** (default checked, only honored server-side when `wpcom_is_proxied_request()` is true)

### Acceptance Criteria (frontend scope)

#### Duplicate detection and blocking

- [ ] Duplicate detection at signup matches on cleaned root domain only (the agency-name match is dropped from this flow).
- [ ] If the cleaned root domain is on the non-unique-domain denylist, the duplicate-check modal does NOT fire. Instead the form shows a validation error directing the user to enter their agency's actual website.
- [ ] When a duplicate is detected (non-denylisted root domain matches an existing agency), the modal does NOT offer a self-service "create duplicate" path. Only Cancel and Contact support are exposed.
- [ ] Modal copy does NOT surface the matched domain (no `{agencyDomain}` interpolation).
- [ ] Modal body includes an inline link "invite you as a team member" pointing to `https://agencieshelp.automattic.com/knowledge-base/invite-team-members/`.

#### Support CTA

- [ ] The "Contact support" button in the modal opens the existing `UserContactSupportModalForm`, prefilled with name, email, agency name, agency URL from the signup form (sourcing email from `getCurrentUser` or `formData.email` depending on which signup path is active).
- [ ] The support submission is tagged `a4a_duplicate_signup_blocked`.

#### Internal-only bypass UI

- [ ] An "Internal Flags" section renders below the modal body when `is_automattician` OR `is_proxied` is true (from the new `/wpcom/v2/agency/signup-context` endpoint, which will be added in the companion wpcom PR).
- [ ] Small italic muted text under the section header explains which condition triggered it (proxy, A11n account, or both).
- [ ] A "Bypass and create new agency anyway" button proceeds with the duplicate signup and passes `bypass_duplicate_check: true` and `skip_hubspot: <checkbox value>` to the signup handler.
- [ ] A "Don't send this signup to HubSpot" checkbox renders, default checked.

#### Tracks events

- [ ] Tracks events fire for all new CTAs (support, cancel, internal-flags bypass, skip-hubspot toggle, non-unique-domain validation).

#### Existing behavior preserved

- [ ] The change is mirrored in the v1 signup form (`client/a8c-for-agencies/sections/signup/signup-form/`) if the same modal exists there.
